# v0.32 to v0.33

## Overview

v0.33 replaces the flat per-type `AircraftPerformance` table with distance-to-go speed profiles. TTG is now calculated using a speed schedule that varies with distance from the runway, rather than a single averaged descent speed. This produces more accurate TTG estimates, particularly for aircraft that decelerate significantly on the approach.

There is one breaking change that requires updates to your `Maestro.yaml`.

## Before You Start

Back up your existing `Maestro.yaml` before making any changes.

## Breaking Changes

### `AircraftPerformance` format replaced with speed profiles

The `AircraftPerformance` section previously held one entry per ICAO type code, each with a single `DescentSpeedKnots` value. This has been replaced with a list of speed profiles. Each profile covers one or more aircraft types using descriptors, and defines a speed schedule as a set of distance-to-go bands.

Before:

```yaml
AircraftPerformance:
  - {TypeCode: B738, DescentSpeedKnots: 220, IsJet: true,  WakeCategory: Medium}
  - {TypeCode: A320, DescentSpeedKnots: 210, IsJet: true,  WakeCategory: Medium}
  - {TypeCode: B77W, DescentSpeedKnots: 250, IsJet: true,  WakeCategory: Heavy}
  - {TypeCode: A388, DescentSpeedKnots: 260, IsJet: true,  WakeCategory: Super}
  - {TypeCode: DH8D, DescentSpeedKnots: 160, IsJet: false, WakeCategory: Medium}
  - {TypeCode: PC12, DescentSpeedKnots: 120, IsJet: false, WakeCategory: Light}
```

After:

```yaml
AircraftPerformance:
  - AircraftTypes: [Jet]
    Speeds:
      - {ThresholdNM: 45, SpeedKnots: 330}
      - {ThresholdNM: 35, SpeedKnots: 310}
      - {ThresholdNM: 25, SpeedKnots: 280}
      - {ThresholdNM: 15, SpeedKnots: 250}
      - {ThresholdNM: 0,  SpeedKnots: 210}

  - AircraftTypes: [Prop]
    Speeds:
      - {ThresholdNM: 45, SpeedKnots: 280}
      - {ThresholdNM: 35, SpeedKnots: 260}
      - {ThresholdNM: 25, SpeedKnots: 230}
      - {ThresholdNM: 15, SpeedKnots: 200}
      - {ThresholdNM: 0,  SpeedKnots: 160}
```

**Steps:**

1. Replace the entire `AircraftPerformance` section with one or more speed profiles.
2. Group aircraft by their approach speed characteristics rather than listing individual type codes. Use `Jet` and `Prop` as a starting point.
3. For each profile, define speed bands covering the full range from TMA entry to the runway. The last band must have `ThresholdNM: 0` to serve as the floor speed for the final approach.
4. If specific type codes need different speeds from their category (e.g. a turboprop that descends faster than average), add a separate profile for that type code. Exact type code matches take priority over category matches.

**AircraftTypes descriptors:**

| Value | Matches |
|-------|---------|
| `Jet` | All jet-powered aircraft |
| `Prop` | All turboprop and piston aircraft |
| `Light` / `Medium` / `Heavy` / `Super` | Aircraft by wake turbulence category |
| `B738`, `A320`, etc. | Specific ICAO type codes |
| `All` | All aircraft (useful as a fallback profile) |

**Speed bands:**

Each band applies when distance-to-go is strictly greater than `ThresholdNM`. The band with `ThresholdNM: 0` covers all remaining distance to the runway. Bands should be listed in descending order of `ThresholdNM`.

---

## Behaviour Notes

- `IsJet` and `WakeCategory` are no longer required in `Maestro.yaml`. These values are still provided by vatSys at runtime and used for matching; they no longer need to be manually configured.
- If no profile matches an aircraft, the first profile in the list is used as a fallback. Consider adding an `All` profile at the end as an explicit fallback.
- TTG values will change after migration. The new profiles more accurately model the speed reduction that occurs on the approach, so TTG estimates will generally be lower than with the previous flat-speed model.
